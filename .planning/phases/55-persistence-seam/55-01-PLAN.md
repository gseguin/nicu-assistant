    TYPES:

    - PersistentValueOptions<T>: interface with key: string, defaultValue: T, codec?: Codec<T>, recover?: (raw: string | null) => T

    - jsonCodec<T>(): Codec<T> — returns { serialize: JSON.stringify, deserialize: JSON.parse as (s: string) => T }. Make it a generic function (not a constant) to allow TypeScript to infer T at each call site.
    - rawStringCodec: Codec<string> — { serialize: (v) => v, deserialize: (v) => v }

    FACTORY:
    - createPersistentValue<T>(opts: PersistentValueOptions<T>): PersistentValue<T>

    Inside the factory, capture: const codec: Codec<T> = opts.codec ?? jsonCodec<T>().

    The returned object has three methods. Use the early-return guard form (per PATTERNS.md) on all three, NOT the positive-wrap form from persist():

    read(): T —
      (1) if typeof localStorage === 'undefined' return opts.defaultValue
      (2) try block: const raw = localStorage.getItem(opts.key); if opts.recover is present return opts.recover(raw) [recover fully owns the path, replaces deserialize+fallback]; if raw === null return opts.defaultValue; return codec.deserialize(raw)
      (3) catch block: return opts.defaultValue with comment "Silent: invalid JSON, security error, or private browsing mode — fall back to default."

    write(value: T): void —
      (1) if typeof localStorage === 'undefined' return
      (2) try: localStorage.setItem(opts.key, codec.serialize(value))
      (3) catch: comment "Silent: private browsing mode or storage quota exceeded."

    remove(): void —
      (1) if typeof localStorage === 'undefined' return
      (2) try: localStorage.removeItem(opts.key)
      (3) catch: comment "Silent: private browsing mode or security error."

    Copy the silent-comment style verbatim from PATTERNS.md.

    NOTE on recover + codec interaction (D-02): when opts.recover is present, codec.deserialize is NOT called on the read path. The outer try/catch is the last-resort fallback if recover itself throws (returns opts.defaultValue). This is intentional — recover is trusted to be total; the outer catch is just defense-in-depth.

    NOTE on JSON.parse('null') edge case (RESEARCH Section 2): add a code comment on the deserialize line noting that JSON.parse('null') returns null (not defaultValue). The four Phase 56 adapters do not store "null" intentionally; future adapters that need nullable values should use recover.

    The file should be ~60-80 lines. No class syntax. No this. No exports beyond those listed above.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser storage → application read path | localStorage content is unvalidated external input on read (could be corrupted by XSS, browser extensions, or manual edits) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-55-01 | Tampering | persistent-value.ts read() / JSON.parse | mitigate | try/catch around JSON.parse + fallback to defaultValue — malformed or adversarially crafted stored JSON never crashes the app or yields unexpected types |
| T-55-02 | Denial of Service | persistent-value.ts write() / localStorage.setItem | accept | Silent no-op on quota/private-mode throw — this is the existing proven pattern across all 5 current callers; the app continues with in-memory defaults |
| T-55-SC | Tampering | npm/pip/cargo installs | accept | Zero new packages in this phase — no install step, no slopcheck needed |

**Assessment:** This phase neither widens nor narrows the existing localStorage attack surface. It consolidates five hand-rolled copies of the same guard+catch pattern into one audited location — this is a net security improvement. There are no HIGH-severity threats introduced. The seam has no PII, no credentials, no network calls, no auth, and no server side. The stored data is clinical calculator inputs the user typed themselves and already stored in localStorage before this refactor. The silent-catch behavior (T-55-02) is the existing proven approach for all five current callers and is appropriate for an offline-first PWA with no recovery path from quota failure.
</threat_model>
